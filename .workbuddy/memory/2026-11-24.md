## 修正问题 2 的真正根因：画布是横的（用户指出）

**用户反馈**："本项目设计的是竖屏游戏，不应该设计为横屏的画布大小。" —— 之前只把留边刷成背景色，治标：`SHOW_ALL` + 横屏窗口里，竖屏 UI 仍被塞进一块横屏画布，只在中间露一条。

**根因**：`settings/v2/packages/project.json` 只有 `__version__`，设计分辨率走编辑器默认 **1280×720（横屏）**；`GameEntry` 又用窗口宽高比推设计高度并 `SHOW_ALL`，等于承认"画布是横的"。

**正确做法（引擎支持）**：`screenAdapter.isProportionalToFrame`（= `ResolutionPolicy.ContainerStrategy.PROPORTION_TO_FRAME`）会让 `Cocos3dGameContainer` 按**设计比例**收成一个框，`screen.windowSize` 也随之变成容器尺寸。
1. 项目设置写死竖屏：`general.designResolution = {width:750, height:1334, fitWidth:true, fitHeight:false}`（schema 从 app.asar 里确认过，键名是 `general.designResolution.*`）。
2. `GameEntry.onLoad` 按窗口比例选策略：`winH/winW < 1334/750` → PROPORTION_TO_FRAME（画布竖屏框居中）；否则 EQUAL_TO_FRAME（铺满窗口，设计高度跟随，上限 2.3）。
3. 画布外的页面底色也刷成 `THEME.bgEdge`（`_paintPageBackdrop`，`sys.isBrowser` 守卫 + `document.body/documentElement.style`），相机清屏色与 `BgFill` 同色。

**实测（构建产物）**：1280×600 → canvas 337×600（竖屏），设计 750×1334，棋盘 580×928；656×900 → 506×900；390×844 → 铺满，设计 750×1623、棋盘 690×1104；750×1334 → 1:1。编辑器预览 7456 同步生效（325×578 竖屏框，无 Missing class）。

**教训**：用户说"黑边"时先问"黑的是什么"——如果黑的是**画布内**，是设计分辨率/容器策略的问题；如果黑的是**画布外**，才是页面底色问题。这次两者都有。

## 用 MCP 把编辑器里的状态直接修正（重启之后）

**做法（全部通过 MCP，不用重启、不用手点）**：

3. `component_set_properties(cc.UITransform.contentSize={750,1334})` + `node_set_transform(position=[375,667,0])`。
4. `scene_save` → 磁盘场景被编辑器重写（对象 15→17：多了 `cc.LightProbeInfo`/`cc.PostSettingsInfo`，3.8.8 新格式，正常）。

**代码加固**：`GameEntry.onLoad` 开头检查 `this.node.getComponents(GameEntry)`，多于 1 个时非首个直接 `destroy()` —— 以后谁再重复挂也不会重复开局。
