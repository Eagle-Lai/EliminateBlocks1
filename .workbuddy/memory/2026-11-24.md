## 本轮学到的硬经验（后续必须遵守）
- **MCP scene_script 可以直接 new Node + addComponent + 设 @property，再由主进程 `scene:create-prefab` 落成 .prefab**——38 个 Prefab 全靠这套管线生成，比 node_create 一格格搭快一个数量级。重建单个 Prefab：asset_delete → scene_script 全量建树 → create-assets（跳过已存在的）→ 清理 __PrefabTemp__（removeFromParent+destroy）→ scene_save。
- **Prefab 之间不要互相引用**：BoardView/PieceView/ChapterMap 等的 @property(Prefab) 留空，运行时用 `assets.getPrefab('prefabs/xxx')` 回退 + BOOT 全量预载，避免鸡生蛋。
- **assertRefs 不要把"有运行时回退"的 Prefab 属性列进去**，否则 onOpen 直接抛错、UIManager 静默把节点 active=false。
- **分包 = 文件夹 .meta userData {isBundle, bundleName}**；`assets/bundles` 本身不能再设 bundle（嵌套分包会被父级吞掉）。
- **verify-assets 的 uuid 引用扫描**能抓出"Prefab 引用了已移动/删除的图"（GameScreen/DailyPanel 的 bg 引用）。
- **release 构建里 constructor.name 会被压缩**，冒烟脚本要用 `cc.js.getClassByName('GameController')` 找组件。
- **内容校验机器人**：GreedyBot + simulateSettle（含特殊块/邻接碎石/糖爆）必须与运行时同一套 core，否则 special/burst 目标全判不可达；stone 目标关的初始盘面**每行至少留 1 个缺口**，否则开局整行"消行"直接清空石块。
- rows/stone 目标按 §7 公式在 40–80 锁内不可达，已按实测下调（报告逐关列出）。
